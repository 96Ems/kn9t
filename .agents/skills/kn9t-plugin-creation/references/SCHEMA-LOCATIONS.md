# Schema Locations

The canonical protocol schemas are generated by `xtask` and committed to the repo.
**Always read these files for the up-to-date wire format.**

## Plugin Protocol Schema

**Path:** `schema/plugin.json`

Contains:
- `host_to_plugin` — Messages the host sends (Hello, Hook, Cancel, Shutdown, ApiResult)
- `plugin_to_host` — Messages the plugin sends (Hello, Result, Chunk, Done, Request)
- `definitions` — Shared types (ToolSpec, ProviderDecl, ModelDecl)

## HTTP API Schema

**Path:** `schema/http.json`

Contains the REST API schema for kn9t-server endpoints.

## Generated Code

**Path:** `schema/generated/`

Contains language-specific type definitions generated from the schemas:
- `go_types.go` — Go structs
- `python_types.py` — Python dataclasses

## Regenerating Schemas

After modifying `kn9t-plugin-sdk` wire types:

```bash
cargo run -p xtask -- generate
```

This updates all schema files and generated code. The pre-commit hook enforces schema/code sync.

## Using Schemas

### For Plugin Authors

Read `schema/plugin.json` directly to understand the exact wire format.
The JSON Schema is language-neutral and describes every message type.

### Key Message Types

| Direction | Type | Purpose |
|-----------|------|---------|
| Host→Plugin | `hello` | Handshake initiation |
| Host→Plugin | `hook` | Invoke tool/hook/provider |
| Host→Plugin | `cancel` | Abort in-flight call |
| Host→Plugin | `shutdown` | Graceful termination |
| Host→Plugin | `api_result` | Reply to plugin's host_api request |
| Plugin→Host | `hello` | Declare capabilities, tools, hooks |
| Plugin→Host | `result` | Atomic reply |
| Plugin→Host | `chunk` | Streaming partial output |
| Plugin→Host | `done` | Final streaming reply |
| Plugin→Host | `request` | Host API call (session_fork, etc.) |
